The Doctrine

## Four Commitments, Written As Constraints.

A principle you can break at will is a preference. These four are written into the architecture, which is what makes them checkable rather than reassuring.

### On-device by default

If a feature can run on the phone, it runs on the phone. The network is a privilege we ask permission for, never an assumption we design around. This is why there is no sync — a copy you cannot see is still a copy.

### Bought once, owned forever

A tool you open daily makes an excellent subscription and a poor deal. We charge once. If the company disappears tomorrow the software keeps working, because nothing about it depends on us still being here.

### No advertising, no telemetry

There is no analytics SDK, no attribution SDK and no crash reporter phoning home. We do not know how many screens you opened today, and we have built ourselves no way of finding out.

### Correct before clever

Arithmetic about somebody’s money is not a place for approximately. Every figure is checked against an independent implementation before it ships, and a feature waits if the maths is not settled.
A privacy policy is a promise about what a company will choose to do. An architecture is a statement about what is possible.

Engineering Standard

## Tested Like Infrastructure, Not Like An App.

Personal finance software fails quietly. A wrong figure looks exactly like a right one, so the only defence is refusing to trust the first implementation of anything.
We publish the failures too. The build report for this site lists eight defects found and fixed in the last pass, including two that had been live for weeks — because a standard nobody can audit is a slogan.
